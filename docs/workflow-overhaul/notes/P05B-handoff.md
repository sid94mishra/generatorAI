## 1. What P06 builds on

- **`WorkflowApprovalService`** (`packages/core/src/services/WorkflowApprovalService.ts`, on `CoreServices.workflowApprovalService`): `listPending(runId)` returns every decision of a run — completion reviews, in-turn gates, parked loops (`kind: 'loop_decision'`), approval and event waits (`kind: 'wait'`, `waitType`) — and, recursively, those of its running sub-workflow children with the chain they came through (`via`). `respond(runId, instanceId, {outcome, feedback?, data?, expectedVersion?}, {actor})` answers any of them through the parent (the owning run is found by instance; a wait's form is validated). WP-6.1's `respond_workflow_approval` and `check_workflow_run` call it; the run digest's `pendingApprovals` already comes from it (`kind`, and `runId` for a child's card).
- **Operator decisions are `exec:agent`**: `approve`, `grant_iterations`, `raise_budget`, `continue_with_input`, `accept`, `accept_iteration`, `deliver_event` (the commands route's `DECISION_COMMANDS`). Everything else is `write:workflows`.
- **Sub-workflow runs** are invocations with trigger `{kind: 'stage', runId, stageRunId}`, principal `system:engine`, idempotency key `subworkflow:<stageRunId>`, lineage (depth ≤ 3, recursion refused), the parent's effective mode as the ceiling. A child is as attended as its root run. `SubworkflowEffects.settledMessage(childRunId)` computes a finished child's declared `outputs`.
- **`describe_workflow` risk flags** (WP-6.1): `planInvocation` has `risks[runs_repo_code]` for checks (5A); maps with `mount_per_item` + `pr_per_item`, and sub-workflows (they start other workflows) are further risks worth listing. Invoke already refuses a draft/missing/archived child and output drift (`subworkflow-*` issues) and warns `map-shared-write-concurrency`.
- **Events** on a run's stream scope: `stage_run.waiting` (in `AgentEvent`), `map.started`, `map.item_started`, `map.item_completed`, `subworkflow.child_started` (outbox events like `loop.*`). A chat bridge (WP-6.2) that re-emits `stage_run.*` should include `stage_run.waiting` in "awaiting approval".
- **Callbacks**: `WorkflowCallbacks` (`CoreServices.workflowCallbacks`) mints `v1.<run>.<instance>.<mac>` tokens; the server key is `<dataDir>/workflow-callback.key`.
