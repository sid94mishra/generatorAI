# H: Independent review of `docs/workflow-overhaul/` (plan v1.0)

Reviewer: independent, read-only. Date: 2026-09-24. Baseline: `desktop_redesign` @ `a83a7bf`.
Scope: README, PHASE-00..09, TRACEABILITY, STATUS, DEVIATIONS, checked against evidence A–G5, the audit HTML, and the code.

---

## 1. Verdict summary

**The plan is not ready to hand to a coding agent as written.** The architecture direction is sound and well evidenced: one spec package, one composer, a CAS engine with a pure `decide()`, a structured loop block, one invocation service, and tools plus a skill. Coverage of the product owner's request is broadly complete. But the review found problems in four areas:

1. **Two blockers in the DB migration path.**
   - The "edit the bootstrap to the final shape" instruction breaks fresh databases. Migration v11 still references the `workflows` table and the `copilot_config*` columns (RV-2).
   - v57 relies on `ON DELETE CASCADE` while foreign keys are **off**, so the migration either fails the runner's FK check or orphans about 7.3k `chat_messages` rows (RV-1).
2. **Several technical designs would not work as written against the actual provider code.**
   - Codex reports `fullToolGating: false`, so the WP-2.7 refusal contradicts the W-19 test (RV-6).
   - The Claude skill mechanism is wrong (RV-7).
   - `submit_output` needs host tools, which opencode and ACP do not support. It also ignores the native structured output that Claude and Codex both have (RV-9).
   - The recovery rule "the prompt message exists, so the turn is settled" conflicts with persisting partial text (RV-10).
   - Prefix replay by global sequence number is unsound under `pipeline()`/`parallel()` (RV-11).
3. **The plan knowingly produces throwaway work despite the no-back-compat rule.**
   - Three successive definition encodings, each with its own migration, and the builder UI rebuilt 2–3 times (RV-13).
   - A v1 engine adapter (`RunDefinitionCache`) and a binding-key rebind for a mode deleted one phase later (RV-20).
   - Run history migrated in v55 and then dropped in v57 (RV-14).
   - It also misses the chat **mount** model entirely, which leaves a legacy workspace path alive for workflows (RV-19).
4. **Process-integrity gaps.**
   - `README.md` claims "v1.0 final, independent review incorporated", and R12 is marked closed, but `REVIEW-LOG.md` does not exist (RV-4).
   - R-3 and every migration WP require pinning in `migrations.lock.json`, which does not exist (RV-3).
   - The migration list is incomplete: `turn_role` on `chat_messages`, `amended_at`, the judge columns and the P07 stream index are missing (RV-17).

About a quarter of P07/P08 is scope the product owner did not ask for: QuickJS dynamic scripts, run diff, pinned-data stage tests, stage cache, OTel and a pricing table. Defer it until P00–P06 ship (§4).

**Recommendation:** fix RV-1..RV-19 before P00 starts. Reorder so the pure spec v2 (with Expression v2 and the SessionSpec *schema*) lands in P01. Defer P08 and most of P07.
