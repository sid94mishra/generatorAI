## Additional defects found by the live campaigns

**Provider failure falsely completed a workflow.** The second scheduled batch iteration displayed a Codex system error while the workflow and automation said Completed ([failure evidence](evidence/157-scheduled-batch-provider-error-misreported.png)). A dead-thread notification emitted an error but resolved the awaited promise. It now rejects while preserving streamed partial text and settling open tools. Protocol regressions cover both system-error and thread-closed notifications; stage tests assert failure without a completion event. Successful manual and scheduled live reruns verify the normal path. The final scheduled runs were `97433902-e58a-4a89-8fa3-07437a8e2e6e` and `eadfcef9-63fd-4588-8d9c-6859cfc9fc6f`. The old audit run remains unchanged as evidence; no historical status migration was performed. Exhaustion/backoff behavior still needs a controlled failure campaign.

**A shorter final answer was replaced by earlier commentary.** The upload retest proved that the agent had read the marker, but its completed view showed “I'll read…” instead. Stage execution selected the longest completion event. It now uses the latest authoritative completion for normal, retry and follow-up turns. A regression sends long commentary followed by a short result. The final live run `704354ff-2d0c-4fdf-8216-dd2a57b6ad4b` displays `PLAIN_UPLOAD_OK_82753`, which was absent from the launch prompt.

**Escape dismissed two UI layers.** Closing a review popover also exited the full-screen pane, and could close the whole pane at narrow width. The pane now respects handled Escape events and dialog event paths. The component regression and real 860 × 600 retest verify that a dialog keeps the underlying pane open while a subsequent standalone Escape dismisses the sheet. Document overflow was zero in both directions. See [narrow review](evidence/171-narrow-keyboard-review.png) and [pane retained after Escape](evidence/172-escape-retains-underlying-pane.png).

## Why these changes

A named file action and explicit line bounds make review possible without precise pointer movement. Keeping the familiar gutter interaction avoids changing the existing pointer workflow. Shared controls retain the product's current theme, focus behavior and sizing rules. Correct error and answer propagation makes the visible workflow status trustworthy; cosmetic status changes would leave retry and recovery decisions wrong. Prepared uploads establish one ordered sequence—create the workspace, stage content, discover it, then start the agent.

These decisions follow the earlier audit's [WCAG keyboard and reflow review](https://www.w3.org/TR/WCAG22/) and [desktop interaction guidance](https://developer.apple.com/design/human-interface-guidelines/). This is not a formal accessibility certification or a new visual theme.

## Remaining review priorities

1. **External/platform environments:** authenticated Git/PR operations, third-party MCP, unavailable providers, microphone/audio, computer permissions, device pairing/remote mode, packaging/updating, Windows and Linux.
2. **Automation recovery:** webhook authentication/signature execution, script datasets, retry exhaustion/backoff timing, persisted recovery after process loss, and long-running resource behavior. The retry form and failure contract were tested, not every recovery combination.
3. **Archive restoration:** archived chats close provider sessions and archive owned workspaces. A correct Restore flow needs session reactivation, workspace-retention checks, and defined behavior when files have been reaped. Existing metadata status updates do not implement that lifecycle. No unsafe status-only restore was added.
4. **Agent browser bridge:** the agent's scoped-tab attachment timeout remains distinct from the successful human-style native browser tests. The generated designer widget's inner HTML still needs its own narrow-width treatment.
5. **Accessibility/scale:** screen-reader, zoom/contrast, large catalogs and sustained performance. Keyboard file review is covered; the third-party gutter button's accessible naming remains library debt.
6. **Coverage limits:** plain uploaded skills/agents need their own complete matrix beyond the prompt retest and existing orchestrated-skill journey. Agent teams, every template/hook/command and every permission/failure branch were not executed. Script upload/edit exists in server routes but the current desktop Scripts pages expose catalog/detail/run/materialize; it is not a verified desktop editing flow.

The isolated audit app is closed, the test schedule is disabled, and the user’s original app instance was not stopped by this audit. The audit harness, downloaded files and databases remain local under `/tmp/gai-desktop-audit`; do not share that directory wholesale because it contains credentials.
