Connect from anywhere with no certificates

Why Claude Remote Control and similar apps never ask anyone to install a certificate, why GeneratorAI does today, and a simpler architecture that works the same on the same network and across networks.

01Why Claude Remote Control needs no certificate

Because no phone or browser ever connects to your machine.

  • The web UI comes from claude.ai, a public site with an ordinary trusted certificate. The phone app talks to Anthropic too.
  • Your machine only connects out. Anthropic's docs: "Your local Claude Code session makes outbound HTTPS requests only and never opens inbound ports on your machine. When you start Remote Control, it registers with the Anthropic API and polls for work… All traffic travels through the Anthropic API over TLS."
  • Anthropic's servers pass messages between your machine and your devices. Every hop uses a normal public certificate, so nothing needs installing.

Codex, Cursor, Warp and VS Code Remote Tunnels follow the same pattern:

  • the UI comes from a public site (chatgpt.com, vscode.dev), or from a native app;
  • the user's machine dials out to a relay;
  • the devices reach it through that relay.

The price is a vendor relay. Most of these relays can read the traffic: Claude Remote Control stores transcripts and is switched off for zero-retention and HIPAA organisations. Codex and VS Code tunnels encrypt end to end through theirs.

02Why GeneratorAI asks for one today

Only one scenario needs a certificate: a browser on another device loading the web UI straight from your computer. Two hard rules cause it.

  1. Browsers only allow the crypto we need on secure pages. Pairing creates a device key in the browser (crypto.subtle). Browsers allow that only on https:// pages or localhost. http://192.168.x.x is neither. That's the "Web Crypto unavailable" error you saw on Windows.
  2. No public certificate authority will certify a home-network address. CA/Browser Forum rules forbid it. Let's Encrypt's IP certificates need a public address it can reach. So HTTPS on a LAN address means a certificate only your machine vouches for, and every browser warns about it until it's installed.

Could we just allow plain HTTP for browsers on the home network? No. Without HTTPS, anyone on the same Wi-Fi can rewrite the web page itself on its way to the browser, and steal the session or approve actions. That's fine at home but dangerous in an office, hotel or café. The secure-page rule exists to stop exactly this.

The root cause is architectural. We made other devices load the UI from your computer. The apps that need no certificate serve the UI from a public site and reach your computer through an outbound relay.

04Cloudflare Tunnel and Tailscale

Cloudflare Tunnel: not implemented

A design existed (docs/CLOUDFLARE_TUNNEL_RELAY_PLAN.md, status "proposed, not yet built"). It was deleted in the release-cleanup commit 84be7f2c. No code launches cloudflared.

  • Quick Tunnels need no account, but they are wrong for this. Cloudflare's own docs: "Quick Tunnels are for testing and development", "no uptime guarantee", a 200 in-flight request cap, a new hostname every time, and "Quick Tunnels do not support Server-Sent Events (SSE)". GeneratorAI streams chats and runs over SSE.
  • Named Tunnels work well, with a stable public HTTPS address and no certificate install. But each user needs a Cloudflare account and a domain, and Cloudflare ends the TLS at its edge, so it can read the traffic. They're a good advanced option, not a default.

Tailscale: works today

With the "your own certificate" feature (D-113), tailscale cert gives a publicly trusted certificate for machine.tailnet.ts.net, so browsers show no warning. Traffic is WireGuard-encrypted end to end, on the same network and across networks. The catch: every device must install Tailscale and join the account. That's great for technical users, but too much to ask by default.

06Recommended approach

One QR code, connect from anywhere, nothing to install.

Why this is the best fit

  • No certificate install, ever, by default. Public certificates cover the hosted site and the relay. Native apps pin in code.
  • The same flow on the same network and across networks. The relay works from anywhere. Native apps use the LAN shortcut automatically.
  • Better privacy than Claude Remote Control. End-to-end encryption through our relay, the way Codex and VS Code tunnels do it. Claude's relay reads and stores transcripts.
  • Only outbound connections from the user's computer. No open ports or router changes, and no LAN exposure needed. That shrinks the attack surface, avoiding the class of exposed-server incidents seen with Ollama and OpenClaw.
  • No OS network prompts for browsers. Chrome's Local Network Access and the iOS and Android local-network permissions don't apply when everything goes through a public relay.

The honest cost

  • We have to run a static website and the relay service. The relay code is already written (apps/relay). It still needs hosting, monitoring and abuse limits.
  • The hosted site serves the browser's code. Users trust GeneratorAI's site, as they trust claude.ai. End-to-end encryption still protects them if the relay itself is compromised.
  • Without internet, browsers on other devices need the advanced direct-LAN mode. Native apps keep working over the LAN.
