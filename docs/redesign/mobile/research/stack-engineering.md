Scope: runtime baseline, performance, component development, testing, visual regression, AI-agent tooling,
architecture/conventions, build/release and accessibility for the GeneratorAI mobile overhaul
(131 boards, iOS 27 + Android 17 variants, 18 themes × light/dark × 7 accents, phone + tablet).

- `code-audit.md` (this folder) — the current mobile code, dependency health, verification gaps.

Method: every version below was read from the npm registry on 2026-09-26 (`npm view <pkg> dist-tags time`), and the
Expo SDK pins were read from `bundledNativeModules.json` inside the `expo@57.0.25` and `expo@58.0.0-preview.7` tarballs.
Behavioural claims cite official docs, changelogs or GitHub. Where a claim is from a secondary source or my inference,
it says so.

### 1.2 React Compiler gotchas for this codebase

- **Reanimated:** read/write shared values with `sv.get()` / `sv.set()` instead of `.value`; never touch them during
  render ([Reanimated docs](https://docs.swmansion.com/react-native-reanimated/docs/core/useSharedValue/)). RNGH 3's hook
  API was designed to be compiler-compatible; the RNGH 2 builder chains (`Gesture.Pan().onUpdate`) are the risky pattern
  ([RNGH 3 upgrade](https://docs.swmansion.com/react-native-gesture-handler/docs/guides/upgrading-to-3/)).
- **zustand 5:** selector hooks (`useStore(s => s.x)` + `useShallow`) are compatible; do not read `store.getState()` in render.
- **MMKV 4:** hooks are fine; imperative reads in render are side effects — move them to effects or initialisers.
- **Escape hatch:** `'use no memo'` per component; incremental rollout through the Babel `sources` filter. Run
  `npx react-compiler-healthcheck@latest` first. Existing hand-memoised rows (`TimelineRow`, `UserMessageRow`) keep
  working; delete the manual memo only when the row is redrawn.

### 1.3 Recommendation — upgrade *before* kit work, as the first M0 task (confidence: high)

1. **Now:** `npx expo install expo@latest --fix` → 57.0.25 / RN 0.86.3 (patch-level, fixes the dev-startup regression).
2. **M0 gate:** move to **SDK 58 stable** as one dedicated upgrade task before any kit component that touches gestures,
   tabs, fonts or `Text` refs is written. Reasons: RNGH 3's hook API, stable native tabs, variable fonts
   (M-14 already assumes SDK 58), the Strict TS API and router core rework all change the code the kit would otherwise be
   written against; doing it after 60 components means rewriting them. Expensify reached the same conclusion
   (upgrade RNGH to 3.x before the 0.88 bump — [Expensify#101442](https://github.com/Expensify/App/issues/101442)).
3. **Enable React Compiler in the same task** (`experiments.reactCompiler: true`), with Reanimated `.get()/.set()` and
   RNGH hook API as lint-enforced conventions from day one.
4. If SDK 58 is still beta when M0 ends: try `expo@next` in a throwaway checkout; adopt only if every native dep in
   `package.json` builds and the smoke loop (§10) passes on both platforms. The sibling `mobile-stack-research.md` table says
   "RNGH 2.32 keep" — that is superseded by SDK 58's RNGH 3.2 pin.

Pitfalls: SDK 58 turns **R8 on** for release (add ProGuard rules for any reflection-based lib; check
`react-native-quick-crypto`, `nitro-modules`); `expo-file-system` `File.write()` becomes async; `NODE_ENV` is set before
`.env` loading; `@expo/ui`/`expo-symbols` become optional peers of expo-router (install explicitly).

## 2. Performance

### 2.1 New Architecture practice in 2026 (what to encode as rules)

- Bridgeless + Fabric + Hermes V1 are the only path; no `Platform.OS` feature flags for old arch.
- Keep work off the JS thread during streaming: batch SSE deltas per frame (the stream store already coalesces), keep
  row components pure, and let the React Compiler memoise.
- Prefer native-backed primitives: Expo UI for leaf controls, `expo-image`, native markdown text, Legend List.
- Measure on **release builds on a device/emulator**, not dev builds (dev mode is several × slower).
- Use `<Activity>` for hidden panes instead of unmounting (keeps scroll/terminal state, stops effects).

### 2.7 Images and startup

- **Add `expo-image`** (SDK-matched; 57.0.5 / 58.0.6): disk+memory cache, placeholders/blurhash, SVG, `transition`
  (SDK 58 adds `skipOnCacheHit` and `svgVariables`). Use for avatars, attachments, browser-pane screenshots.
- **Startup:** Hermes V1 bytecode is default. Expo Router already loads routes lazily on native: routes are
  `getComponent` thunks, only the active route and its layouts load at startup
  ([Calazans](https://andrei-calazans.com/posts/2026-06-04-expo-router-screen-level-lazy-loading/)); async route
  bundle splitting on native is dev-only/experimental even in SDK 58 ([docs](https://docs.expo.dev/router/web/async-routes/)).
  Rule: keep `app/_layout.tsx` and group layouts thin; no heavy module (xterm bundle, markdown engines, highlight tables)
  imported from a layout.
- **Bundle:** keep `scripts/check-bundle.mjs` (server-module leak guard) and use Expo Atlas
  (`EXPO_ATLAS=true npx expo export --platform ios|android`, then `npx expo-atlas .expo/atlas.jsonl`; `expo-atlas` 0.4.3)
  for size investigations
  ([analyzing bundles](https://docs.expo.dev/guides/analyzing-bundles/)).

## 7. Architecture and conventions

### 7.1 Layers (mirror the web, enforced with `eslint-plugin-boundaries` 7.2.0)

```text
apps/mobile/
  app/                  Expo Router route files only: re-export a feature screen, set options/layout. No logic.
  src/ui/**             presentational kit (+ .stories.tsx). No stores, api, router, blocks, features.
    ui/platform/**      the ONLY place allowed to import @expo/ui/swift-ui, @expo/ui/jetpack-compose, Platform.OS branches.
  src/blocks/**         query-aware parts shared by ≥2 features (e.g. StatusBadge+feed row, gate cards, composer shell).
  src/features/<area>/  screens + domain parts; data only via hooks/*Queries.ts or stores; no cross-feature imports.
  src/app-shell/**      providers, drawer/pane shell, deep-link handling, theme bootstrap.
  src/platform/**       native bridges (device key, biometrics, notifications, widgets) — never rewritten casually.
  modules/, plugins/, targets/   native code + config plugins (CNG inputs).
packages/client-core, client-runtime, shared, design-tokens   React-free (unchanged rule).
packages/client-react (new, per mobile-stack-research §sharing)   React-only view-model hooks; must not import
                                                                  react-native, react-dom or styling.
```

Lint rules to add to the root `eslint.config.mjs` (mobile block): boundaries element types as above;
`no-restricted-imports` for `react-native` `Platform` outside `ui/platform` and `src/platform`; no `@tanstack/react-query`,
`client-transport` in `features/`; no `StyleSheet.create` with colour literals; `better-tailwindcss` rules with the Uniwind
global CSS as `entryPoint` (`no-unknown-classes`, `no-conflicting-classes`, `no-restricted-classes` for arbitrary values
`\[.+\]`, palette classes, `text-white/black`); a `check:design` ratchet script for mobile (arbitrary values, hex/rgb,
literal `style` colours, stories-present). Pitfall: Uniwind's platform variants (`ios:`, `android:`, `native:`) and
data selectors must be recognised by the plugin — verify against Uniwind's CSS entry and add ignores only if needed
([no-restricted-classes](https://github.com/schoero/eslint-plugin-better-tailwindcss/blob/main/docs/rules/no-restricted-classes.md),
[Uniwind platform selectors](https://docs.uniwind.dev/api/platform-select.md)).

### 7.2 Platform variants — rule of thumb (confidence: high)

- **Styling differences** (radius, type ramp, spacing): Uniwind `ios:`/`android:` variants or geometry tokens (M-04). Never
  `Platform.select` in features.
- **Different native implementation, same contract** (menus, pickers, switches, segmented controls): one folder per
  component in `ui/` with `Component.tsx` (shared props type + fallback), `Component.ios.tsx`, `Component.android.tsx`;
  Metro resolves the extension; the shared `Component.types.ts` is imported by both so `tsc` enforces parity; stories import
  the base name and are captured on both platforms.
- **Behavioural branches** (back handling, haptics vocabulary): helpers in `src/platform`, not inline `Platform.OS`.

### 7.3 Monorepo

- Expo configures Metro for monorepos automatically since SDK 52; the docs say to **delete** manual `watchFolders`,
  `nodeModulesPaths`, `extraNodeModules`, `disableHierarchicalLookup`; pnpm isolated installs are supported since SDK 54 and
  `autolinkingModuleResolution` is automatic in monorepos since SDK 55 ([monorepos](https://docs.expo.dev/guides/monorepos/)).
  Recommendation (confidence: medium): in the SDK 58 upgrade task, remove the four manual keys and the unhoisted-package
  fallback, keep the three genuine resolver rules (crypto alias, `@generatorai/shared` client entry, NodeNext `.js` → `.ts`),
  run `npx expo start --clear` and `npx expo-doctor` (1.20.4); if duplicate React appears, restore only
  `disableHierarchicalLookup`. Leave `.npmrc shamefully-hoist=true` alone (whole-repo setting; not a mobile decision).
- Keep shared packages React-free; add `packages/client-react` only when the first hook is genuinely shared by web and
  mobile (composer state machine wrapper, attention store binding) — no speculative extraction.

  ([Android 16 behaviour changes](https://developer.android.com/about/versions/16/behavior-changes-16)).

  third-party `.so`, e.g. quick-crypto, MMKV, nitro) ([page sizes](https://developer.android.com/guide/practices/page-sizes)).
  Android 17 = API 37; no Play deadline for it yet — test on an API 37 image when Google ships stable system images.
- **Apple:** since 2026-04-28 uploads must be built with **Xcode 26 / iOS 26 SDK** ([Apple](https://developer.apple.com/news/upcoming-requirements/),
  [Expo](https://expo.dev/blog/app-store-connect-minimum-sdk-26)). The `UIDesignRequiresCompatibility` Liquid Glass opt-out
  was announced as temporary for Xcode 26 ([Donny Wals](https://www.donnywals.com/opting-your-app-out-of-the-liquid-glass-redesign-with-xcode-26/));
  assume Liquid Glass is mandatory under the Xcode 27 SDK — the boards already target iOS 27. The iOS 27 SDK **requires the
  UIScene lifecycle** (the repo's `withSceneLifecycle` plugin; built in with SDK 58). By Apple's usual cadence the Xcode 27
  SDK becomes mandatory around April 2027 (inference, not announced).

**Recommendation (confidence: medium-high):**
- Kit: every interactive `ui/` component takes `accessibilityLabel`/role through its props type (required for icon-only
  variants), with an RNTL test per component.
- Loop: `node apps/mobile/e2e/a11y-check.mjs <snapshot.json>` over the agent-device snapshot — fail on unlabelled
  interactive nodes and targets below 44 pt (iOS) / 48 dp (Android).
- Per batch: an XCUITest audit target generated by a config plugin, run over the main routes (iOS), and Accessibility
  Scanner by hand on Android for new screens.
- **Dynamic Type matrix:** iOS content sizes `L` (default), `XXXL`, `AX3`, `AX5` (`xcrun simctl ui <udid> content_size
  accessibility-extra-extra-extra-large` or `agent-device settings text-size`); Android `font_scale` 1.0, 1.3, 2.0 (Android 14+
  scales non-linearly to 200 %). Kit `Text` sets a per-role `maxFontSizeMultiplier` policy from tokens (body unbounded,
  dense chrome capped), never `allowFontScaling={false}` except for the terminal.
- Also test: VoiceOver/TalkBack order on the chat screen (drawer, transcript, composer, pane) once per batch, Reduce Motion,
  Bold Text, Increase Contrast (map to the high-contrast theme where designed).

## 10. Proposed per-task "Done loop" for mobile (macOS; iOS Simulator + Android Emulator)

Mirrors the web loop in `.claude/CLAUDE.md`. Stop and fix at the first failure. Per the testing-strategy memory, steps
marked **[batch]** run once per batch of tasks, not per task.

```text
Prereqs (once per machine): DEVELOPER_DIR or `sudo xcode-select -s /Applications/Xcode.app`; JDK 17 (JAVA_HOME);
  $ANDROID_HOME/platform-tools on PATH; Android system images android-36 (+ android-37 when stable) and AVDs
  "gai-phone" / "gai-tablet"; iOS sims pinned in apps/mobile/vrt/devices.json (one iPhone Pro size, one 13" iPad);
  pnpm install (agent-device, maestro wrapper, odiff); node scripts/mobile/doctor.mjs (wraps `agent-device doctor`,
  `npx expo-doctor`, checks JDK/Xcode/adb and prints the device ids).

0. ui/blocks task: start the dev server with Storybook enabled; query the storybook-mobile MCP for existing components
   before creating one (use it / add a variant + story; never fork in a feature).
1. pnpm --filter @generatorai/mobile typecheck                (+ typecheck of any touched package)
2. pnpm --filter @generatorai/mobile lint                     (boundaries, better-tailwindcss, compiler rules, a11y rules)
3. pnpm --filter @generatorai/mobile check:design             (arbitrary values, literal colours, stories-present ratchet)
4. pnpm --filter @generatorai/mobile exec vitest related --run <changed logic files>
   pnpm --filter @generatorai/mobile exec jest --findRelatedTests <changed ui/blocks files>      (kit contracts)
5. Native build only if needed: node scripts/mobile/fingerprint.mjs → if the fingerprint changed since the installed
   build: npx expo run:ios --device <pinned sim> and npx expo run:android --device <pinned avd> (dev client);
   otherwise keep the installed builds and just `agent-device metro reload`.
6. Walkthrough, both platforms (agent-device, one session each):
     agent-device open dev.generatorai.app --platform ios|android
     agent-device open "generatorai://<route>"                 (deep link straight to the screen / story)
     agent-device snapshot -i --json > shots/…/snapshot.json   (assert testIDs, roles, labels, states)
     interact: click/fill/scroll by @ref or role+name; wait for text/state
     agent-device screenshot for: light + dark (settings appearance) × default + AX text size (settings text-size)
     agent-device logs --app-only → no new errors / red boxes / yellow boxes
   → docs/redesign/shots/mobile/<route>/<platform>-<device>-<mode>-<size>.png
   Tablet routes: repeat on the iPad sim and tablet AVD (portrait + landscape).
7. node apps/mobile/e2e/a11y-check.mjs shots/…/snapshot.json   (labels, roles, 44pt/48dp targets)
8. Board compare: node scripts/redesign/render-boards.mjs --only=<MBoard> && node scripts/redesign/side-by-side.mjs …
   → open each compare PNG → write docs/redesign/shots/mobile/<route>/DIFF.md
   (Matches / Intentional deviations / Defects), per platform variant (iOS 27 board vs iOS shot, Android 17 vs Android).
9. The feature's Maestro flow: maestro test --platform ios|android apps/mobile/.maestro/<area>/<flow>.yaml
   (new screen → write or port the flow in the same task; delete the replaced e2e/*.mjs).
10. [batch] node scripts/redesign/mobile-vrt.mjs --grep <component|route>   (Storybook stories × variants × both
    platforms, odiff vs baselines; --update for intended changes, listed in the commit)
11. [batch] Full Maestro suite (tag smoke+full) on both platforms; perf check (release build: transcript scroll +
    streaming scenario, agent-device perf frames --json vs budget); bundle check (pnpm bundle:check);
    XCUITest accessibility audit on main routes; Dynamic Type sweep (AX5 / font_scale 2.0) on changed screens.
12. [batch] Native/system-surface changes (widgets, Live Activities, notifications, deep links): agent-device push
    <payload>, open deep links, verify on both platforms; release build smoke (expo run --configuration Release /
    --variant release) because R8 and Hermes release differ from dev.
Then: old files deleted (no shims), README progress table updated, commit `redesign(<task-id>): …`.
```

Why this shape: steps 1–4 are seconds; step 5 avoids 5–10 minute native builds when only JS changed; step 6 uses the
accessibility snapshot as both the interaction map and the assertion source (cheaper than screenshot reasoning), and
screenshots only for the design comparison; steps 10–12 are the expensive, flake-prone parts and run once per batch.

## Pitfalls summary

1. **Xcode 27 Device Hub** breaks tools that look for Simulator.app or old SimulatorKit paths (Claude Code's simulator
   panel, XcodeBuildMCP/AXe, Maestro Studio streaming). `xcrun simctl` still works; prefer agent-device/Maestro CLI.
2. **`xcode-select` points at CLT and there is no JDK** on this Mac — fix before the first loop, or every Android/Maestro
   step fails.
3. **SDK 58 majors** (RNGH 3, webview 14, Strict TS API, router core rework, R8 default) — one upgrade task, verified on
   both platforms in release mode, before the kit.
4. **enriched-markdown re-parses whole documents** — feed it blocks, not the whole message.
5. **VRT determinism** depends on pinned device + runtime, status bar/demo mode, animations off, frozen clock and bundled
   fonts; baselines are per device/runtime — re-baseline deliberately after an Xcode/AVD image update.
6. **Experimental agent surfaces** (Storybook RN MCP, `@expo/agent-cli`, local Expo MCP) will change; keep them behind
   scripts in `scripts/mobile/` so a breaking change is fixed in one place.
7. **Android 16+ large screens ignore orientation locks** when targeting API 36 — tablet layouts must be resizable in
   both orientations.
8. **Emulator image mismatch:** only android-35 is installed; edge-to-edge enforcement and large-screen rules need an
   API 36 image to reproduce.
