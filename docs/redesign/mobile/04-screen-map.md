## 1. Route tree

### 1.1 Rules

1. **Paths mirror web** (`docs/redesign/04-screen-map.md` §1, R-3, R-4, R-5). A `generatorai://<path>` link, an `AttentionItem.href` and a `SearchResult.href` are web-shaped paths and resolve to the same mobile route without a mapping table. Mobile-only routes (sheets, `/pickers/*`, `/search`, `/servers`, `/needs-you`, `/workspaces/*`, `/scope-request`, `/share`) never collide with web paths (MD-79).
2. **Routes contain no logic** (MD-14). Each file under `app/` is a layout, presentation options, or `export { default } from '@/features/<area>/<Screen>'`. Presentation options for every route live in the owning `_layout.tsx` (not in the screen).
3. **One native Stack** under `app/(app)/_layout.tsx`, wrapped by the app shell: left `SidePanel` (drawer/sidebar) + right `SidePanel` (pane) inside `AdaptiveLayout` (MD-18, MD-24). The expo-router Drawer and Tabs navigators are not used (MD-17). Route sheets and full-screen modals are presented by the Stack over the whole shell.
4. **Unpaired root.** `app/_layout.tsx` redirects to `/pair` when no server is paired and to `/revoked` when the current server revoked this device.
5. **Search params are untrusted.** Every screen parses its params through a zod schema in `features/<area>/params.ts`; `?dock=` goes through `parseDockLinkTab`.

This covers New chat → agent picker → Customize capabilities, New chat → model picker, New chat → project picker and server folder browser, Add codebase → server folder browser, and the run sheet's per-stage overrides and plan preview. A sheet whose action leads to another sheet (execution detail → approval) closes first, then presents the next one. Every picker returns its value through the owning draft store (`features/chats/newChatDraftStore` for New chat, a zustand store with the MMKV-persisted unsent draft; the editor's form state for the agent editor), never through route params (MD-62).

### 1.6 Deep links (`generatorai://…`)

**Mechanism.** `app/+native-intent.tsx` (`redirectSystemPath`) passes every incoming URL — OS link, notification `href`, widget, Live Activity, quick action, share extension hand-off — to `resolveDeepLink()` from the shared module (MG-20, moved from `apps/desktop/src/main/deep-link-route.ts`). Rules (MD-34):
- Query keys are reduced to the shared allowlist `DEEP_LINK_QUERY_KEYS`: `pair`, `dock`, `tab`, `kind`, `run` (desktop, `deep-link-route.ts:22`) plus `server` and `code` (added by MG-20). Everything else, the hash and `.`/`..` segments are dropped.
- `command/<id>` runs only a command in `DEEP_LINK_COMMAND_IDS` (`packages/shared/src/ui-contract/commands.ts:149`: `chat.new`, `workflow.new`); any other id is rejected and logged.
- `server=<serverId>`: if that server is paired, switch to it first (MG-19); if not, ignore the link and show an error Toast "Not paired with that server". Without `server`, the current server is used.
- `pair` links only pre-fill the code; they never auto-submit. There are no universal links.
